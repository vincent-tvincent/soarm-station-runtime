# Continuous-operation revision — November 13, 2026

The user requested removal/revision of unnecessary actuation safeguards that interrupt smooth continuous operation. The planning chat reviewed the exact deployed baseline `048fdf52906804d82d028eacbd846658f529650e`; the implementation chat remained the sole code writer. No PID, calibration, travel/speed limits, 0.12-rad target-lead bound, source-freshness window, torque-loss protection or support-torque policy was relaxed.

## Behavior changes

1. **Continuous STREAM lifetime.** Omitted/zero ROS duration now means no total STREAM deadline when the profile has no ceiling. Fresh authenticated input/liveness, END, cancellation, hold or fault govern the session. An explicitly requested duration and a configured optional `max_stream_duration_s` remain effective. Browser and native operator no longer silently request120 seconds; native `--seconds` is optional. Finite INLINE paths/steps remain bounded, with duration derived from actual work when omitted. Configurable defaults: max INLINE/path3600s; model step default30s/max3600s; final settling2s.
2. **One grant across normal operations.** Successful INLINE completion releases the operation while preserving the same healthy operator/controller grant and final admitted command reference. Each next motion still needs an explicit new operation. Explicit disable, hold/cancel, END, actual control-WebSocket disconnect, source expiry, fault and restart revoke permission. There is no new idle timer or browser authority channel. Stateless HTTPS callers must explicitly hold/disable after their sequence. The UI labels retained IDLE permission as waiting for a new operation and exposes Hold/disable.
3. **Continuous streamed paths.** A STREAM trajectory stays active at its settled endpoint and accepts later fresh replacements. The old final-settle timer applies only before that endpoint has settled, not to later harmless drift. Replacement is a bounded positional path anchored at the current admitted commanded reference/time, validated against current measured state and velocity/lead bounds. It does not re-seed from lagged measurements or create a queued rolling-chunk planner. Intermediate waypoints still do not require separate settle/approval.
4. **Ordered, constant-memory sparse intent.** MODEL/TRAJECTORY stream COMMANDs now require positive `semantic_revision`, distinct from transport `sequence`. Higher revision validates fully then atomically replaces intent; equal revision requires identical input ID/body hash and acknowledges without restart; lower revision is permanently retired and rejected. Only the current canonical tuple/high-water is retained, so there is no256-intent lifetime failure. Current-revision retry horizon lasts while that revision remains current in the same operation. A higher revision is a new intent even if it reuses an old label; producers should use a fresh input ID. DIRECT remains latest-only.
5. **Rate/lead behavior under lag and contact.** Lead limiting cannot project an already admitted body reference backward in a rate-violating jump. Out-of-envelope reference waits with diagnostics; optional no-progress policies are explicitly actuator/mode configured and default off. Expected gripper contact/compliance does not freeze body advancement. The previously admitted bounded grasp goal is retained without deepening its lead, and requested release/correction proceeds at the usual rate. Body-only trajectories preserve that grasp reference and do not demand a gripper-position settle they never commanded. Explicit gripper-position trajectories retain their completion check.
6. **Native MODEL outcomes and residency.** The adapter uses released SyncInferenceEngine / RemoteInferenceEngine and explicit ACTION/WAIT/HOLD/FAULT. Weight/backend residency is separate from task generation; task reset clears native policy/processor/queue state without reloading an unchanged checkpoint. Unconditioned policies can run with empty instruction; language-conditioned profiles enforce language on both input modes and can wait for their first task before starting native work. Preparation does not fake a successful motor send or hold: native final commit wraps actual owner dispatch, and hold acknowledgement follows successful actual owner hold. Camera decoding/model work remains outside the device thread; remote eligibility/pop is lightweight owner-side work.
7. **Native timing and stale work.** The arbitrary200ms returned-target TTL is replaced by native action cadence and original source provenance/horizon. Local cached chunk actions keep the chunk's capture time; remote actions keep native provenance. BOOTTIME acquisition age is converted to the same-host monotonic domain without restamping delayed observations. Inference underrun/wait is explicit and does not invent/interpolate unbounded stale actions. Job token/profile/deadline is captured at submission; obsolete exceptions/timeouts cannot revoke a newer intent. Stale profile loads are retired/closed. Terminal remote failure cannot auto-retry the faulted operation; a fresh explicitly authorized operation may create a new admitted native session while the server model remains its deployment.

## Protocol migration

`OperationInput` adds uint64 `semantic_revision`; feedback adds `last_accepted_semantic_revision`. Rebuild/restart all affected ROS participants: retaining the numeric JSON schema version is not old DDS binary compatibility. DIRECT JSON clients need no new field. Sparse JSON COMMANDs without a positive revision receive `SEMANTIC_REVISION_REQUIRED` before publication/admission; no silent replay fallback is used. Transport windows and increasing sequence still apply to new commands and retries. Clients that explicitly keep sending `duration_s:120` still request that limit; update/reload them to use the new continuous default.

For a sparse producer: wait for READY, send revision1 with an input ID/body and current transport window/sequence, wait for acknowledgment, then increment revision for the next semantic intent. A retry preserves revision+ID+body but uses a fresh valid transport window/sequence. Query current accepted revision after rejection. An invalid replacement does not mutate or cancel the last valid intent; a producer unable to establish its requested intent must explicitly hold/cancel rather than keep the old task alive accidentally.

## Preserved limitations

One operation per arm; position/time trajectories only; no coordinated multi-arm planning, collision checking, continuous Cartesian-path guarantee, force controller or general rolling-chunk scheduling. Physical elbow following error remains approximately3.2 degrees under unchanged stock gains, with its already-qualified0.07-rad completion tolerance. Native calls use one bounded worker; a canceled native call may need to return before new native work proceeds, although its obsolete results have no actuation authority. Shared synchronous command IPC and transport backpressure remain measurable latency limitations; source-loss protections intentionally stop stale input.
